# 0005 · Next 15 e React 19; auditoria volta a bloquear

*10/10/2026 · aceita · substitui a [0003](0003-auditoria-de-dependencias.md)*

## Contexto

O Next 14.2.33 tinha uma falha crítica e outras altas sem correção na linha 14 (ver 0003).
Ao subir para o Next 15, o `npm audit` ainda acusou dois pontos:

- o Next 15.5 traz uma cópia própria do PostCSS (8.4.31) com falhas altas; a correção do
  Next só existe no 16;
- o nodemailer 6 tinha falhas altas (entre elas, risco de vazar credenciais SMTP e negação
  de serviço no leitor de endereços), corrigidas só no 10.

## Decisão

- Next 15.5.27, React 19 e `eslint-config-next` 15.5.27. O Next 16 fica para depois:
  muda mais coisa (o `middleware.ts` vira `proxy.ts`, `next lint` sai) e não é necessário
  para zerar a auditoria.
- `overrides` no `package.json` faz o Next usar o mesmo PostCSS do projeto (8.5.29, já
  corrigido). O PostCSS só é usado na hora do build.
- nodemailer 10.0.16. O app só usa `createTransport` e `sendMail`, que não mudaram.
- A auditoria volta a bloquear o merge (`npm audit --omit=dev --audit-level=high`).

## Mudanças no código

- Em rotas com segmento dinâmico (ex.: `/api/conta/sessoes/[id]`), o Next 15 entrega os
  `params` como Promise; `rotaAutenticada` (`server/http/rota.ts`) agora espera por eles.
- `NextRequest.ip` deixou de existir; o IP vem de `x-forwarded-for` ou `x-real-ip`.
- `useRef` exige valor inicial no React 19 (`lib/store.tsx`).

## Consequências

- Ao subir o Next para 16, remover o `overrides` se o Next já trouxer um PostCSS corrigido.
- `next lint` está obsoleto no Next 15 e some no 16; migrar para o ESLint direto quando for
  ao 16.
